# 3.1.0

Planned release based on published 3.0.0.

## Breaking changes and migration

- Remove `DataResult` instance scope/transform dispatcher fields and their fluent
  setters. Configure each observation through helper parameters instead.
- Add optional `scope` and `transformDispatcher` parameters to `unwrap`, `data`
  and all error helpers. Loading helpers accept optional `scope`. Null preserves
  the existing wrapper defaults: Main/SupervisorJob and Default for transforms.
- Recompile consumers: observation method signatures change. Replace
  `result.scope(owner).data { ... }` with `result.data(scope = owner) { ... }`.
  Existing positional callbacks need `func = callback`; trailing lambdas remain
  valid. See [migration examples](../core-concepts.md#migrate-removed-result-setters).
- Constructor, equality, copy, destructuring and synchronous `transform` retain
  their value semantics. No execution configuration lives on the result.

## Other changes

- Limit sequence emptiness checks to one iterator probe and cardinality checks to
  two elements. Two values distinguish zero, one and multiple items without
  traversing the tail; tail side effects/errors are no longer evaluated.
  Constrained-once sequences remain single use; no replay/cache is added.
- Explain result snapshots, application events and persisted state with core,
  Compose and state examples, including cancellation and restoration boundaries.
- Add common tests for independent per-call settings, direct helpers, cancellation,
  transformation dispatchers and bounded sequence inspection.
