# 2.3.1

Compose API changes, typed error observers and maintenance based on tag `2.3.0`.

**Compatibility:** this candidate contains breaking Compose API changes; review the release version before publishing.

## Changes

- Add stateless `DataResultContent(result)` and `DataResult.Content` rendering, with flow collection through `ComposableDataResult(flow)` and `Flow<DataResult<T>>.Unwrap`.
- Remove the Compose side-effect callback; callers manage effects explicitly with `LaunchedEffect`.
- Replace the builder and `AnimationConfig` with an optional `transitionSpec`; animations are disabled by default.
- Keep animation identity stable for payload updates; status, data/error presence and collection shape determine transitions. Sequence keys do not consume their data.
- Build observer registrations in a mutable list once per content lambda instead of copying an atomic list for every registration.
- Rename `ObserveComposableWrapper` to `DataResultContentScope` and mark the receiver scope of its `On...` methods with `DataResultContentDsl`.
- Add typed error observers and DataResult helpers using `KClass` or reified exception types. Typed and untyped handlers are additive.
- Give reified error helpers distinct JVM names to avoid erased-signature collisions.
- Cover direct rendering, animation keys, payload updates and typed error filtering with common tests.

- Update Android Gradle Plugin from 9.4.0 to the stable 9.4.1 patch.

- Update Android SDK setup to `android-actions/setup-android@v4` (Node 24 and the maintained command-line tools provided by the action), explicitly installing `platform-tools` instead of the unavailable legacy `tools` package.

- Apply one generated-class filter to module reports and root coverage aggregation, including HTML, XML and verification.
- Disable Codecov report discovery so only `build/reports/kover/report.xml` is uploaded; module reports cannot reintroduce excluded classes.
- Exclude only Android-generated `BuildConfig`, `R` and nested `R` classes; retain handwritten code and existing coverage floors.
- Configure Android test JVM access required by Robolectric 4.17 on JDK 21.
- Update the GitHub App token action to v3 (Node 24 on hosted runners).
- Use this versioned changelog directly for the GitHub Release, without a duplicate root notes file.
- Document coverage scope, local commands and the audited dependency versions.
- Refresh the JavaScript Yarn lockfile for Kotlin 2.4.20's tooling dependencies.
- Update MkDocs Material from 9.7.6 to 9.7.7.
- Verify the existing Gradle 9.7.1 distribution with its official SHA-256 checksum.

## Compatibility

The Compose API changes are source and binary breaking: the builder, its extensions and `AnimationConfig` are removed, and `ObserveComposableWrapper` is renamed to `DataResultContentScope`. Migrate to `DataResultContent` or `flow.Unwrap`, passing `transitionSpec` directly and handling side effects with `LaunchedEffect`. Release versioning must account for this incompatibility before publishing. Existing minimum Android SDK and KMP targets remain unchanged.
Coverage measures JVM/Android host tests; Apple, JS and Wasm tests remain in the test suite but do not contribute coverage counters.

Dependencies on other Arch repositories use versions available in Maven Central, rather than unpublished patch candidates.
